# AI Diabetic Retinopathy Detection Model

This directory contains the machine-learning component of the AI-powered
Diabetic Retinopathy (DR) Screening System. The model analyzes retinal fundus
photographs and predicts one of five diabetic-retinopathy severity grades.

This is an experimental screening pipeline. It is not a standalone clinical
diagnostic device and has not been clinically validated by this repository.

## System overview

The complete pipeline is:

```text
Input fundus photograph
        |
        v
Image-quality assessment
        |
        +---- Failed check ---> INSUFFICIENT / recapture image
        |
        v
Resize to 224 x 224
        |
        v
ImageNet normalization
        |
        v
NVIDIA EfficientNet-B0 backbone
        |
        v
Five-class DR classifier
        |
        v
Softmax probabilities
        |
        v
Predicted DR grade and confidence
        |
        v
Grad-CAM heatmap and overlay
        |
        v
Structured JSON result
```

The main implementation files are:

- [src/model.py](src/model.py): builds EfficientNet-B0 and loads the NVIDIA checkpoint.
- [src/dataset.py](src/dataset.py): loads APTOS-style CSV/image data and creates dataloaders.
- [src/image_quality.py](src/image_quality.py): performs non-learned image-quality checks.
- [src/train.py](src/train.py): trains and checkpoints the classifier.
- [src/inference.py](src/inference.py): executes the full quality, prediction, and explanation pipeline.
- [src/gradcam.py](src/gradcam.py): generates Grad-CAM visualizations.
- [src/evaluate.py](src/evaluate.py): evaluates the best checkpoint and saves metrics.
- [src/predict.py](src/predict.py): provides simple classifier-only inference.

## Technology stack

MATLAB and Simulink are core technologies in this project. The system is a
multi-environment medical-AI pipeline: MATLAB performs the primary fundus image
processing and retinal-analysis work, Simulink models the telemedicine system
and scalability behavior, and the existing Python/PyTorch component performs
the final five-class DR classification.

```text
MATLAB + Image Processing Toolbox
                -> quality assessment, enhancement, anatomy, lesion candidates
                -> analysis images, masks, measurements, and JSON

Python + PyTorch + CUDA
                -> preserved NVIDIA EfficientNet-B0 classifier
                -> probabilities, DR grade, and Grad-CAM

Simulink
                -> acquisition, buffering, network, queues, specialists, throughput
                -> telemedicine and 100,000-patient scalability simulation
```

### MATLAB retinal-analysis platform

- MATLAB: primary implementation environment for image quality, enhancement,
        retinal structures, lesion candidates, reporting, and batch analysis.
- Image Processing Toolbox: grayscale/color conversion, filtering, CLAHE,
        morphology, connected components, skeletonization, overlays, and image
        measurements.
- MATLAB JSON/CSV support: integration-ready retinal-analysis manifests and
        batch summaries.
- MATLAB figures and `exportgraphics`: original/enhanced comparisons, anatomy
        overlays, vessel masks, lesion-candidate masks, and final reports.

The MATLAB entry point is [matlab/runRetinalAnalysis.m](matlab/runRetinalAnalysis.m).
The configurable MATLAB values are in
[matlab/defaultRetinalConfig.m](matlab/defaultRetinalConfig.m).

### Simulink telemedicine platform

- Simulink: system-level simulation, separate from CNN training.
- Patient-arrival source and fundus-camera workflow.
- Acquisition buffer and image-compression stages.
- Network bandwidth, latency, and packet-loss assumptions.
- Image-quality gate, AI processing, risk routing, specialist queue, and
        specialist-capacity stages.
- Throughput, latency, queue length, utilization, failed-transmission, and
        bottleneck outputs.

The Simulink model is generated by
[simulink/buildTelemedicineModel.m](simulink/buildTelemedicineModel.m) and is

## Disease classes

The classifier has five output classes. Labels are read from the `diagnosis`
column in `data/train.csv`.

| Grade | Class | Clinical category represented by the label |
| ---: | --- | --- |
| 0 | No DR | No visible diabetic-retinopathy signs |
| 1 | Mild DR | Mild non-proliferative diabetic retinopathy |
| 2 | Moderate DR | Moderate non-proliferative diabetic retinopathy |
| 3 | Severe DR | Severe non-proliferative diabetic retinopathy |
| 4 | Proliferative DR | Proliferative diabetic retinopathy |

The model predicts the overall grade. It does not independently segment or
count microaneurysms, hemorrhages, exudates, cotton-wool spots, venous beading,
or neovascularization.

## Inference pipeline

The complete inference flow is implemented by `run_inference()` in
[src/inference.py](src/inference.py).

### 1. Image validation

The input path is checked and the image is loaded with OpenCV for quality
assessment. If any fundamental quality check fails, the classifier is not run.

### 2. Quality gate

The quality module returns either `SUITABLE` or `INSUFFICIENT`. An insufficient
image produces a result with no DR prediction and a recommendation to recapture
the fundus image.

### 3. Model loading

The best checkpoint is loaded into the EfficientNet-B0 model. The checkpoint
contains the model state dictionary, optimizer state, training epoch, best
macro-F1 score, and class names.

### 4. Prediction

The valid image is resized and normalized, then passed through EfficientNet-B0.
The five output logits are converted to probabilities with softmax. The largest
probability becomes the predicted grade.

### 5. Explanation

Grad-CAM is generated for the predicted class unless `--no-gradcam` is used.

### 6. Result serialization

The final result contains image quality, prediction probabilities, confidence,
and paths to the generated Grad-CAM images. The `--json` option prints this
result as structured JSON.

## Image-quality gate

The checks in [src/image_quality.py](src/image_quality.py) are deterministic
heuristics, not a separate neural network.

### Resolution

The minimum accepted image dimensions are:

```text
Width:  640 pixels
Height: 480 pixels
```

### Brightness

The grayscale mean brightness must be between 35 and 220:

- Below 35: `TOO_DARK`
- Above 220: `TOO_BRIGHT`
- Otherwise: `GOOD`

### Contrast

Contrast is estimated as the standard deviation of grayscale pixel values. The
minimum accepted value is 25.

### Blur and sharpness

Sharpness is estimated using the variance of the grayscale Laplacian:

```text
blur_score = variance(Laplacian(grayscale_image))
```

The minimum accepted score is 3.0. Lower values are marked `BLURRY`.

### Fundus visibility

The module applies thresholding, morphological operations, and connected
component analysis to estimate how much of the image contains a fundus-like
region. The minimum accepted visibility is 0.50.

This is only a rough visibility heuristic. It is not retinal segmentation.

### Quality score

The numerical quality score is weighted as follows:

| Component | Weight |
| --- | ---: |
| Resolution | 15% |
| Brightness | 20% |
| Contrast | 20% |
| Blur | 25% |
| Fundus visibility | 20% |

The final status still requires every fundamental check to pass. A high score
does not override an individual failed check.

## Image preprocessing

### Training preprocessing

Training transforms in [src/dataset.py](src/dataset.py) are:

1. Resize to `224 x 224`.
2. Random horizontal flip with probability 0.5.
3. Random rotation up to 10 degrees.
4. Color jitter:
   - Brightness: 0.15
   - Contrast: 0.15
   - Saturation: 0.10
   - Hue: 0.02
5. Convert to tensor.
6. Normalize using ImageNet statistics.

### Validation and inference preprocessing

Validation and inference use only:

1. Resize to `224 x 224`.
2. Convert to tensor.
3. ImageNet normalization.

The normalization values are:

```text
mean = [0.485, 0.456, 0.406]
std  = [0.229, 0.224, 0.225]
```

The current pipeline does not explicitly crop the circular fundus, remove black
borders, or locate the optic disc and macula before classification.

## Model architecture

### Transfer learning backbone

The model uses NVIDIA's ImageNet-pretrained EfficientNet-B0 checkpoint:

```text
nvidia_efficientnet-b0_210412.pth
```

The original ImageNet classifier has 1,000 outputs. It is removed and replaced
with a five-output diabetic-retinopathy classifier.

The checkpoint loading and key remapping are implemented in
[src/model.py](src/model.py). The code verifies that the only missing weights
are the new classifier's weight and bias.

### EfficientNet-B0 components

The backbone contains:

- A convolutional stem
- Seven MBConv stages
- Depthwise-separable convolutions
- Squeeze-and-excitation channel attention
- Batch normalization
- SiLU activations
- Residual connections when shapes permit
- A final 1x1 convolution producing 1,280 feature channels

The B0 stage configuration is:

```text
Kernels:       3, 3, 5, 3, 5, 5, 3
Strides:       1, 2, 2, 2, 1, 2, 1
Repeats:       1, 2, 2, 3, 3, 4, 1
Expansions:    1, 6, 6, 6, 6, 6, 6
Channels:      16, 24, 40, 80, 112, 192, 320
```

### MBConv block

An MBConv block generally performs:

```text
Input
  |
  v
1x1 expansion convolution
  |
  v
Depthwise convolution
  |
  v
Squeeze-and-excitation attention
  |
  v
1x1 projection convolution
  |
  v
Residual addition when input/output shapes match
```

Depthwise convolution reduces computation by processing channels separately.
Squeeze-and-excitation learns which feature channels are useful for the current
image. Residual connections make the deeper network easier to optimize.

### Five-class classifier head

The final classifier is:

```text
Adaptive average pooling
        |
Flatten
        |
Dropout, p = 0.2
        |
Linear layer, 1280 -> 5
```

The output is five raw logits. Softmax converts those logits into class
probabilities:

```text
P(class i | image) = exp(logit_i) / sum(exp(logit_j))
```

The class with the highest probability is returned as the prediction.

## Training pipeline

Training is implemented in [src/train.py](src/train.py).

### Dataset loading

The dataset loader expects:

```text
data/train.csv
data/train_images/<id_code>.png
```

The CSV must contain:

```text
id_code, diagnosis
```

The loader verifies the CSV columns, label range, and presence of every image.

### Train/validation split

The current configuration uses:

```text
Training split:   80%
Validation split: 20%
Random state:     42
Batch size:       16
```

The split is stratified by diagnosis to preserve approximate class proportions.

### Class imbalance correction

The classes are imbalanced, so training uses inverse-frequency class weights:

```text
weight(class) = total_samples / (number_of_classes * class_samples)
```

These weights are supplied to `CrossEntropyLoss`, causing mistakes on rare
classes to contribute more to the training loss.

### Two-stage fine-tuning

#### Phase 1: train the classifier

For the first three epochs:

```text
EfficientNet backbone: frozen
Classifier head:       trainable
Learning rate:         1e-3
```

#### Phase 2: fine-tune the whole network

Starting with epoch 4:

```text
Entire model:          trainable
Learning rate:         1e-4
```

Other training settings are:

```text
Total epochs: 15
Optimizer:    AdamW
Weight decay: 1e-4
```

When CUDA is available, mixed precision is enabled to reduce GPU memory usage
and improve throughput.

### Checkpoint selection

The best checkpoint is selected using validation macro-F1 rather than accuracy.
Macro-F1 gives each class equal importance, which is more informative for this
imbalanced medical dataset.

Training writes:

- `checkpoints/best_model.pth`
- `checkpoints/last_model.pth`
- `results/training_history.json`
- `results/confusion_matrix.csv`
- `results/classification_report.txt`

## Grad-CAM explainability

Grad-CAM is implemented in [src/gradcam.py](src/gradcam.py). The selected target
layer is:

```python
model.features.conv
```

The process is:

1. Run a forward pass.
2. Select the predicted class logit.
3. Backpropagate that score.
4. Capture feature-map activations with a forward hook.
5. Capture gradients with a backward hook.
6. Average gradients spatially to obtain feature-channel weights.
7. Calculate a weighted sum of the feature maps.
8. Apply ReLU and normalize the activation map.
9. Resize the map to the original image dimensions.
10. Render a heatmap and a blended overlay.

Grad-CAM shows image regions that influenced the selected prediction. It is not
a lesion segmentation mask and does not prove that the model identified a
clinically meaningful lesion.

## Medical explanation output

The model builds the explanation from the current prediction rather than
returning a fixed response. It reports the predicted class, its probability,
the runner-up class, the confidence margin, a certainty band, the complete
class probability distribution, and numeric Grad-CAM saliency evidence when
Grad-CAM is enabled. It then combines that evidence with concise clinical
context and follow-up guidance:

| Predicted class | Medical context | Recommended next step |
| --- | --- | --- |
| No DR | No visible signs identified by the model | Continue routine screening and diabetes care |
| Mild DR | Early non-proliferative retinal changes may be present | Arrange routine dilated eye-care follow-up |
| Moderate DR | More retinal vascular damage and progression risk | Arrange ophthalmology assessment soon |
| Severe DR | Advanced non-proliferative changes and increased progression risk | Seek prompt specialist assessment |
| Proliferative DR | Advanced category associated with abnormal new vessels and bleeding risk | Seek urgent ophthalmology assessment; emergency care for sudden or severe vision loss |

For Level 0 (No DR) and Level 1 (Mild DR), the output prioritizes prevention,
diabetes control, and routine eye screening. For Level 2 and above, it
prioritizes clinically meaningful explainable-AI evidence: live class
probabilities, the runner-up class, confidence margin, certainty, and Grad-CAM
saliency statistics when enabled.

## Prevention guidance in explainable AI

The explainable-AI output now includes a `prevention_guidelines` field with
clinically cautious, non-diagnostic prevention advice. This guidance is
especially emphasized for No DR and Mild DR predictions, where the system is
intended to support ongoing disease prevention and good diabetic-eye-care
habits rather than urgent specialist escalation.

The prevention guidance includes:

- glycemic, blood-pressure, and lipid control
- adherence to the recommended retinal-screening schedule
- routine follow-up with the treating eye-care clinician
- prompt reporting of blurred vision, floaters, flashes, eye pain, or sudden
  visual changes

This guidance is included in both the English and Hindi clinical explanations
and is preserved in the JSON output for downstream medical dashboards or QA
review.

These descriptions explain the model output; they are not a diagnosis. The
model does not independently confirm microaneurysms, hemorrhages, exudates,
neovascularization, macular edema, or treatment indications. Clinical review
is required for every positive or concerning result.

## Local LLM explanation

The pipeline can call a local OpenAI-compatible LLM for every successful
prediction. The default endpoint is Ollama:

```powershell
ollama pull llama3.2
ollama serve
```

The inference command automatically uses:

```text
Endpoint: http://127.0.0.1:11434/v1/chat/completions
Model:    llama3.2:latest
Timeout:  120 seconds (allows the first model load)
```

Override the endpoint, model, or timeout with environment variables:

```powershell
$env:LOCAL_LLM_BASE_URL = "http://127.0.0.1:11434/v1/chat/completions"
$env:LOCAL_LLM_MODEL = "llama3.2"
$env:LOCAL_LLM_TIMEOUT = "20"
```

Only structured prediction evidence is sent to the LLM: class probabilities,
confidence, confidence margin, certainty, and Grad-CAM statistics when
available. The fundus image and patient identifiers are not sent. If the local
LLM is unavailable, the command returns `llm_explanation.status` as
`unavailable` and keeps the deterministic clinical explanation as a fallback.

Generated files are saved under:

```text
results/gradcam/
results/inference/
```

## Limitations and future improvements

### Current limitations

- There is no independent held-out test set in the current training script.
- The reported metrics come from one stratified validation split.
- Patient-level grouping is not implemented; the available loader splits image rows.
- The quality gate uses hand-designed heuristics rather than a calibrated quality model.
- Softmax confidence is not calibrated probability or clinical certainty.
- Grad-CAM is an explanation aid, not proof of correct lesion localization.
- The model predicts severity as ordinary categories, even though the grades are ordinal.
- No explicit lesion segmentation, fundus cropping, or anatomical landmark detection is used.
- The current result does not provide sensitivity, specificity, or referral thresholds.
- The data does not establish performance across cameras, populations, or clinical sites.

### Recommended next improvements

1. Create patient-level train, validation, and test splits.
2. Add an independent external dataset for validation.
3. Report sensitivity, specificity, ROC-AUC, PR-AUC, and quadratic weighted kappa.
4. Calibrate probabilities using a validation-set calibration method.
5. Evaluate image-quality thresholds against expert-labeled quality data.
6. Add fundus-region cropping and artifact/background handling.
7. Investigate ordinal or cost-sensitive classification losses.
8. Use specialist review to validate Grad-CAM regions.
9. Measure performance by camera type and demographic subgroup.
10. Define an explicit human-referral workflow for uncertain or high-risk cases.

This repository should therefore be treated as a research and engineering
prototype for diabetic-retinopathy screening, not as a replacement for a
qualified ophthalmologist or a regulated medical device.

### Python image-quality gate

Implemented in [src/image_quality.py](src/image_quality.py). These are the
original Python inference thresholds:

| Metric | Implemented value | Pass condition |
| --- | ---: | --- |
| Minimum width | 640 px | width >= 640 |
| Minimum height | 480 px | height >= 480 |
| Minimum brightness | 35 | grayscale mean >= 35 |
| Maximum brightness | 220 | grayscale mean <= 220 |
| Minimum contrast | 25 | grayscale standard deviation >= 25 |
| Minimum blur score | 3.0 | variance of Laplacian >= 3.0 |
| Minimum fundus visibility | 0.50 | largest region / image area >= 0.50 |

The Python visibility heuristic uses:

```text
Gaussian blur kernel: 9 x 9
Threshold:            20th percentile of blurred grayscale pixels
Morphological kernel: 15 x 15 ones matrix
Morphology:           close, then open
Selected region:      largest external contour
```

The Python quality score weights are:

| Component | Weight | Score details |
| --- | ---: | --- |
| Resolution | 15% | 100 if passing, otherwise 40 |
| Brightness | 20% | 100 - distance from 128 scaled by 40/128, clipped at 0; 25 outside range |
| Contrast | 20% | min(100, contrast / 60 * 100); halved when below threshold |
| Blur | 25% | min(100, blur score / 200 * 100); halved when below threshold |
| Fundus visibility | 20% | min(100, visibility * 100) |

The Python gate is strict: resolution, brightness, contrast, blur, and fundus
visibility must all pass. A failed image returns `INSUFFICIENT`, no prediction,
and no Grad-CAM.

### MATLAB quality decision

Implemented in [matlab/defaultRetinalConfig.m](matlab/defaultRetinalConfig.m)
and [matlab/assessQuality.m](matlab/assessQuality.m). MATLAB uses the same
main engineering limits, with an additional decision layer:

| MATLAB parameter | Value | Meaning |
| --- | ---: | --- |
| `minWidth` | 640 px | Minimum image width |
| `minHeight` | 480 px | Minimum image height |
| `minBrightness` | 35 | Minimum grayscale mean on a 0-255 scale |
| `maxBrightness` | 220 | Maximum grayscale mean on a 0-255 scale |
| `minContrast` | 25 | Minimum grayscale standard deviation on a 0-255 scale |
| `minSharpness` | 3 | Minimum Laplacian variance on an 8-bit-equivalent scale |
| `minFundusVisibility` | 0.50 | Minimum fundus mask fraction |
| `enhanceScoreThreshold` | 70 | Score at or above this can be `GOOD` |
| `recaptureSharpness` | 1.5 | Below this is always `INSUFFICIENT` |
| `recaptureVisibility` | 0.25 | Below this is always `INSUFFICIENT` |

MATLAB computes:

```text
brightness = mean(grayscale[0..1]) * 255
contrast   = std(grayscale[0..1]) * 255
sharpness  = var(Laplacian(grayscale[0..1])) * 255^2
visibility = number of fundus-mask pixels / total pixels
```

The MATLAB score is:

```text
score = 0.15 * resolution_score
          + 0.20 * brightness_score
          + 0.20 * contrast_score
          + 0.25 * sharpness_score
          + 0.20 * visibility_score
```

The status rules are:

```text
If sharpness < 1.5 OR visibility < 0.25 OR resolution fails:
        INSUFFICIENT
Else if all five checks pass AND score >= 70:
        GOOD
Else if all five checks pass OR score >= 45:
        ENHANCE
Else:
        INSUFFICIENT
```

MATLAB fundus-mask details:

```text
Threshold:            20th percentile of grayscale pixels
Closing element:      disk radius 7
Opening element:      disk radius 5
Selected region:      largest connected component
```

`GOOD` images are preserved. `ENHANCE` images enter the enhancement stage.
`INSUFFICIENT` images are rejected before retinal analysis; enhancement is not
allowed to hide severe blur, missing fundus content, or inadequate resolution.

### MATLAB enhancement parameters

Implemented in [matlab/enhanceFundus.m](matlab/enhanceFundus.m):

| Parameter | Value | Operation |
| --- | ---: | --- |
| CLAHE clip limit | 0.01 | Adaptive luminance contrast enhancement |
| Background Gaussian sigma | 25 | Large-scale illumination estimate |
| Median filter window | `[3 3]` | Per-channel denoising |
| Unsharp radius | 1.0 | Controlled sharpening radius |
| Unsharp amount | 0.35 | Controlled sharpening strength |
| Color space | CIE Lab | Luminance processing while preserving color channels |
| Output range | 0-255 | Saved as 8-bit PNG |

The sequence is:

```text
RGB image
  -> grayscale illumination estimate using Gaussian sigma 25
  -> background subtraction and mat2gray normalization
  -> Lab conversion
  -> CLAHE on L channel with clip limit 0.01
  -> replace luminance with corrected/CLAHE luminance
  -> 3 x 3 median filter on each RGB channel
  -> unsharp masking, radius 1.0 and amount 0.35
  -> clip to [0, 1] and convert to uint8
```

The module records before/after brightness, contrast, and sharpness. These
metrics describe image transformation only; they do not prove an accuracy
improvement.

### MATLAB anatomical-analysis thresholds

Implemented in [matlab/detectOpticDisc.m](matlab/detectOpticDisc.m),
[matlab/locateFovea.m](matlab/locateFovea.m), and
[matlab/segmentVessels.m](matlab/segmentVessels.m).

#### Optic disc

```text
Fundus mask threshold:       20th grayscale percentile
Bright candidate threshold:  99th percentile inside fundus mask
Closing disk radius:         5
Minimum candidate area:      0.002 * total image area
Maximum candidate area:      0.20 * total image area
Maximum eccentricity:        < 0.98
Confidence cap:              candidate area / (0.03 * image area), capped at 1
```

The largest valid bright candidate is selected. Output includes center `(x,y)`
in pixels, radius, bounding box, confidence, and a mask.

#### Fovea estimate

The fovea is not detected by a trained model. The prototype uses optic-disc
geometry:

```text
Direction from disc:         [-1.0, 0.12], normalized
Distance from disc:          2.5 * optic-disc radius
Estimate marker radius:      max(6, round(0.6 * optic-disc radius)) pixels
Coordinate bounds:           clipped to image dimensions
Confidence:                  local darkness score, clipped to [0, 1]
```

This is an anatomical estimate, not clinically validated fovea localization.

#### Vessels

```text
Input channel:               green channel
CLAHE clip limit:            0.01
Background element:          disk radius 9
Vessel sensitivity:          0.45
Small-object removal:        8 pixels
Cleanup:                     close disk radius 1, then open disk radius 1
Fundus mask percentile:      20th green-channel percentile
```

Outputs include binary mask, skeleton, vessel density, vessel area percentage,
skeleton length in pixels, branching-point count, and a reserved tortuosity
proxy currently set to `NaN`.

```text
vessel_density = vessel_mask_pixels / fundus_mask_pixels
vessel_area_percentage = 100 * vessel_density
```

### Softmax, confidence, and Grad-CAM values

The classifier returns five logits. Softmax converts them to probabilities:

```text
probability_i = exp(logit_i) / sum(exp(logit_j)) for j = 0..4
```

Confidence is only the largest softmax probability. It is not calibrated
clinical certainty and is not the same as validation accuracy.

Grad-CAM uses `model.features.conv`, averages gradients over spatial dimensions,
multiplies the resulting channel weights by activations, applies ReLU, and
normalizes to `[0, 1]`. The inference overlay uses alpha `0.30`; the standalone
Grad-CAM script uses alpha `0.40`. Heatmaps are resized to the original image
dimensions and saved as JPEG files.
